Project Overview ​

Hyperliquid Recovery Bot: Flagged Address Solution ​

Hyperliquid Recovery Bot is a Telegram assistant that helps users recover assets from flagged or restricted Hyperliquid addresses.

💡 Need immediate help? Start from the "Start Here" section below.

Product Positioning ​

This tool is a dedicated Telegram recovery assistant for users whose address can connect in the frontend but cannot operate assets due to high-risk restrictions.

Typical frontend warning in this scenario:

Action blocked: Address flagged for suspicious activity. Your address has been flagged as high risk by a third-party screening tool. This frontend interface does not support connection to the Hyperliquid blockchain by high risk addresses.

In this scenario, the frontend typically shows a red warning overlay and disables or restricts common operation buttons. The bot helps you check what can be handled now, guides you through recovery, and sends funds back to the same address on Arbitrum.

Who Should Use This ​

  • You can access the private key or mnemonic for the address but typically cannot fully operate it in the Hyperliquid frontend.
  • You want a guided recovery flow instead of handling everything manually.
  • You need clear fee disclosure before executing the emergency withdrawal.

What You Get ​

  • Full account detection across spot assets, perpetual positions, vault assets, and staked assets.
  • A guided multi-step recovery flow with real-time progress.
  • Unified fee presentation: Service Fee, Withdrawal Fees, Total Cost, You Will Receive.
  • On-chain verifiability with transaction hashes.

Recovery Scope ​

  • Spot assets: non-USDC assets are sold to USDC.
  • Perpetual positions: eligible positions are closed as part of recovery.
  • Vault assets: assets that can be withdrawn now are handled first; temporarily unavailable assets are left for a later run.
  • Staked assets: the bot handles staking-related balances step by step and tells you when to run again if waiting is required.

Security Principles ​

  • Use only the official bot entry.
  • Never provide your private key or mnemonic to any person, group, form, or website outside the bot's official recovery flow.
  • Use transaction hashes and on-chain results to verify what was completed.

Fee Principles ​

  • Service Fee: 0.5% of recovered value, minimum 1 USDC.
  • Withdrawal Fees: 2 USDC total (two Hyperliquid withdrawals, 1 USDC each).
  • Total Cost: Service Fee + Withdrawal Fees.
  • You Will Receive: Estimated Recoverable Value - Total Cost.

Start Here ​

  1. Open bot: https://t.me/HyperliquidRecoveryBot
  2. Read Quick Start
  3. Review Asset Recovery
  4. Check Fee and Settlement
  5. Review Security and Privacy

Operational Notes ​

  • Final withdrawal goes to the Arbitrum address corresponding to the source address (same address).
  • Settlement is not always instant after withdrawal submission. Arrival time depends on Hyperliquid processing and may take several to more than ten minutes.
  • Result pages may show: completed, partial, waiting_to_rerun, or failed.
  • partial means some assets were handled, but more work may still be needed.
  • waiting_to_rerun means the bot needs you to come back later after a waiting period ends.
  • If nothing could be handled yet, the result will not be shown as completed.

Asset Recovery ​

Hyperliquid Asset Extraction: Emergency Withdrawal Workflow ​

The Asset Recovery pipeline provides an automated safeguard to extract stuck funds from a flagged Hyperliquid address and execute an emergency withdrawal to your Arbitrum wallet.

Inputs Required ​

Prepare the following before execution:

  1. Source address (flagged address)
  2. Private key or mnemonic (signing only)

Standard 7-Step Pipeline ​

The bot generates and executes steps based on detected assets. Ineligible steps are skipped automatically.

  1. Check account status
  2. Convert spot assets (non-USDC -> USDC)
  3. Close or convert perpetual positions as needed
  4. Withdraw vault assets that are currently available
  5. Handle staking and withdrawable balance
  6. Collect service fee
  7. Complete final withdrawal

Step Behavior ​

1) Account Preparation, Spot, and Perp ​

  • Account status: if account setup requires adjustment before recovery, the bot handles that first.
  • Spot: sells non-USDC assets into USDC.
  • Perp: handles eligible positions and closes or converts them as needed for recovery.

2) Vault ​

  • Currently withdrawable assets: withdrawn in current run.
  • Locked assets or vault equity with no current withdrawable amount: shown as waiting/locked in preview and results, then retried after unlock or withdrawability returns.

3) Staking (Important) ​

The bot distinguishes between already-unstaked balance, still-staked balance, and pending-withdrawal balance.

Two practical paths may occur:

  • Faster path (2 runs): if some staking balance is already ready for the next stage, part of it can be withdrawn in the first run and the rest follows after the waiting period.
  • Standard path (3 runs): if the balance is still fully staked, recovery usually needs an unstake stage and then a later withdrawal stage.

The bot output always includes rerun guidance based on current state.

Fees and Settlement ​

  • Service Fee: 0.5%, minimum 1 USDC
  • Withdrawal Fees: 2 USDC
  • Total Cost: Service Fee + Withdrawal Fees
  • You Will Receive: Estimated Recoverable Value - Total Cost

See Fee and Settlement for formulas and examples.

How to Read Results ​

Execution output includes step-level status and final summary:

  • Recovered Amount
  • Actual Fees
  • Transaction hashes for on-chain verification

Note: after withdrawal submission, settlement to Arbitrum is asynchronous and depends on Hyperliquid processing speed (often several to more than ten minutes).

Status mapping is documented in Execution Status.

If the result page says more waiting is required, follow the suggested rerun time.

Retry Strategy ​

  • Network issue: rerun directly.
  • Lock or waiting state: rerun at suggested time.
  • Input mismatch (address/key): fix inputs and rerun.

Best Practices ​

  1. Run address detection before recovery to confirm asset structure.
  2. No destination input is required; withdrawal defaults to the source address on Arbitrum.
  3. For staking or locked vault cases, set reminders and rerun at unlock windows.

Fee and Settlement ​

Fee and Settlement ​

This page explains what fees you may pay, how they are calculated, and what you can expect to receive.

Fee Terms ​

  • Service Fee: 0.5% of recovered value, minimum 1 USDC.
  • Withdrawal Fees: Hyperliquid charges 1 USDC per withdrawal.
  • Total Cost: Service Fee + Withdrawal Fees.
  • You Will Receive: Estimated Recoverable Value - Total Cost.

Estimated Recoverable Value means the assets that can actually be handled in this run. Assets that are still locked or waiting are not counted yet.

Fee Structure ​

Recovery usually includes two withdrawals, so Withdrawal Fees = 2 USDC:

  1. Service fee withdrawal: 1 USDC platform fee
  2. Final withdrawal: 1 USDC platform fee

Withdrawal Fees = 2 USDC
Total Cost = Service Fee + Withdrawal Fees
You Will Receive = Estimated Recoverable Value - Total Cost

Execution Status ​

Execution Status ​

The recovery system uses two layers of status: step-level statuses describe each operation, while task-level outcomes explain how to understand the entire recovery run and what to do next.

Task-Level Outcomes ​

OutcomeMeaningRecommended Action
completedThis run produced actual progress or recovered funds, and no immediate rerun is neededNo immediate rerun needed
partialThis run only partially progressed, or recovered nothing while assets still remain blocked/waitingReview the summary and follow up as needed
waiting_to_rerunThis run progressed successfully, but protocol waiting or lock windows remainRerun after the waiting window ends
failedThis run was interrupted by a fatal errorFix the root cause before retrying

Step-Level Statuses ​

Status Matrix ​

StatusIconMeaningRecommended Action
completed✅Step fully completedWait for next steps
completed_partial⚠️Partial success, some assets skipped or failedReview notes and rerun if needed
completed_waiting⏰Operation succeeded but protocol waiting period appliesRerun at suggested time
skipped_locked🔒Assets currently lockedWait for unlock and rerun
skipped_no_assets➖No eligible assets for this stepNo action required
failed_system_error❌System-level failureRetry later or contact support
failed_user_error⛔Input or configuration issueFix input and retry
failed_network_error🌐❌Network or RPC issueCheck network and retry

Typical Interpretations ​

  • ⚠️ completed_partial: common when only part of vault/staking assets are currently executable.
  • ⏰ completed_waiting: common in staking, where execution succeeds but unlock windows remain (for example, 1-day or 7-day waiting periods).
  • 🔒 skipped_locked: not a hard failure; it indicates protocol lock state.
  • If the whole run is only skipped_* and no funds are actually recovered, the task-level outcome becomes partial, not completed.

When to Rerun Recovery ​

  • If the task-level outcome is waiting_to_rerun, rerun after the suggested unlock time.
  • If the task-level outcome is completed, no immediate extra action is usually required.
  • If the task-level outcome is partial, review the remaining issues before deciding whether to rerun now.
  • If step outputs include failed_* and the task-level outcome is failed, resolve the root cause first, then rerun.

Security and Privacy ​

Security and Privacy ​

This page explains how to use the bot more safely and what you can verify yourself.

Safe Use Basics ​

  • Use only the official bot entry.
  • Never provide your private key or mnemonic to any person, group, form, or website outside the bot's official recovery flow.
  • If you cannot confirm that you are using the official bot, stop and verify before continuing.
  • Never let private keys, mnemonics, or full signatures appear in screenshots or chat records.

What You Can Verify ​

  • Key steps provide transaction hashes or clear execution results.
  • You can verify transaction status and fund movement on-chain.
  • You can use the source address, received amount, and fees to check the result yourself.

Safe Operation Practices ​

  1. Use only the official bot entry: @HyperliquidRecoveryBot.
  2. Operate from a private device and network; avoid public Wi-Fi.
  3. Verify the source address before confirming (withdrawal settles to the same address on Arbitrum).
  4. Outside the bot's official recovery flow, never share, screenshot, forward, or paste private keys or mnemonics anywhere.

Risk Boundary ​

  • The bot cannot bypass platform rules such as lock periods, waiting periods, or minimum withdrawal limits.
  • If some assets are still waiting or locked, come back and run recovery again after the required time.
  • If the private key or mnemonic does not match the address, the bot will stop the process.
  • If anyone asks you to provide credentials outside the official bot flow, treat it as suspicious and stop.

Glossary ​

Glossary ​

This page explains the common words you may see during detection and recovery.

Fee Terms ​

  • Service Fee: 0.5% of recovered value, minimum 1 USDC.
  • Withdrawal Fees: Hyperliquid withdrawal fee, usually 2 USDC total.
  • Total Cost: Service Fee + Withdrawal Fees.
  • You Will Receive: estimated/actual user settlement amount.

Accounts and Assets ​

  • SPOT: regular token balances in your spot account.
  • PERP: perpetual positions or balances related to perpetual trading.
  • VAULT: assets held in vaults; some may be temporarily locked.
  • STAKED: HYPE balances that are in a staking-related state.

Staking States ​

  • HYPE-STAKED: HYPE is still actively staked and cannot be withdrawn immediately.
  • HYPE-UNSTAKED: HYPE has left active staking and is ready for a later step.
  • HYPE-PENDING: withdrawal has been initiated and is still in the waiting period.

Step-Level Statuses ​

  • completed: this step finished successfully.
  • completed_partial: this step finished only in part; some assets may still need follow-up.
  • completed_waiting: this step finished, but you must wait before the next action.
  • skipped_locked: this step was skipped because the asset is currently locked.
  • skipped_no_assets: this step was skipped because there was nothing eligible to process.
  • failed_*: this step failed because of a system, input, or network issue.

Task-Level Outcomes ​

  • completed: this run made real progress or recovered funds, and you do not need to rerun it right now.
  • partial: this run only finished in part, or nothing was recovered yet while some assets are still blocked or waiting.
  • waiting_to_rerun: this run progressed correctly, but you still need to wait and run it again later.
  • failed: this run stopped because of a fatal error.

Q: When is asset recovery needed? ​

A: When your address is flagged as high-risk and:

A: Spot and perpetual assets are usually recovered quickly. For staked assets, recovery usually takes 2-3 runs depending on current state:

  • Optimized path (2 runs): when undelegated balance already exists
  • Standard path (3 runs): when only delegated balance exists (typically 1 day + 7 days windows)

Q: Can the recovery process be cancelled? ​

A: Once confirmed to start recovery operation, it cannot be cancelled. Therefore, please carefully check all information before confirmation.

Q: Is the private key secure? ​

A: The bot handles staking states automatically and tells you when to rerun:

Q: What if my vault assets are locked? ​

A: The bot will skip locked vault assets:

  • Wait for the lock period to end
  • Then run recovery again to withdraw them

Q: Can I specify withdrawal to a specific address? ​

A: No. Recovery does not require destination input. Funds are withdrawn to the Arbitrum address corresponding to the source address.

Q: What to do if recovery fails? ​

A: First check which task-level outcome appears on the result page:

  • failed: this run was interrupted by a fatal error; review the cause before retrying
  • partial: this run recovered some assets, but remaining assets still need attention
  • waiting_to_rerun: this run progressed correctly, but you must wait for protocol windows to end before the next run

If the final outcome is truly failed, the bot will automatically retry on network failures. If it continues to fail:

  1. Check your internet connection
  2. Verify private key is correct
  3. Check error message
  4. Contact support if needed

  • Incorrect private key length (should be 64 hexadecimal characters)
  • Private key does not match address
  • Extra characters included during input

Q: How to handle network errors? ​

A: When encountering network errors:

  1. Check if network connection is stable
  2. Try switching to a more stable network
  3. Wait a few minutes and retry

Q: What to do if API calls fail? ​

A: API call failures may be due to:

  • Hyperliquid API temporarily unavailable
  • Network connection issues
  • Request frequency too high
  • Recommend retrying later

🆘 Emergency Situations ​

Q: What to do if errors occur during recovery process? ​

A: If errors occur during recovery process:

  1. Don't panic, record error information
  2. Check if network connection is normal
  3. Check whether the result page shows partial or waiting_to_rerun, since these do not always mean the run failed

Q: What to do if assets don't arrive on Arbitrum? ​

A: If assets do not arrive on the source address on Arbitrum:

  1. Check transaction hash status in blockchain explorer
  2. Confirm the source address is correct and can receive on Arbitrum
  3. Wait for Hyperliquid processing and additional confirmations (arrival may take several to more than ten minutes)
